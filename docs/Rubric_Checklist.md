# Rubric and submission checklist

The uploaded project guideline was previously summarized as: problem statement/dataset (10), implementation (30), report (10), viva (20), LinkedIn engagement (10), GitHub contribution (20). Confirm exact phrasing and evidence requirements against the instructor's original PDF before final submission.

## 10 — Problem statement and dataset
- [ ] Research question and target defined clearly.
- [ ] UCI source cited; features and limitations explained.
- [ ] Explain why `-200` is missing and why blank rows are removed.

## 30 — Implementation
- [ ] Import and preprocessing run from a clean R session.
- [ ] EDA figures generated.
- [ ] At least five regression algorithms trained.
- [ ] Validation tuning separated from final test evaluation.
- [ ] MAE, RMSE, R² and prediction plots generated.
- [ ] High-pollution error audit discussed.
- [ ] R output CSVs reviewed and final numbers inserted into report.

## 10 — Report
- [ ] Fill student/institution/course details on title page.
- [ ] Replace reference benchmark table with the actual `outputs/test_metrics.csv` from R.
- [ ] Add screenshots of RStudio execution if required.
- [ ] Include limitations and source citation.

## 20 — Viva
- [ ] Explain target, predictors, time-aware split, imputation and scaling.
- [ ] Explain the five algorithms and why KNN/SVR require scaling.
- [ ] Explain MAE, RMSE and R².
- [ ] Explain why this is estimation, not future forecasting.
- [ ] Explain model limitations and high-pollution error audit.

## 10 — LinkedIn
- [ ] Publish only after actual R results are generated.
- [ ] Include repository link and 2–3 honest findings.
- [ ] Do not claim environmental deployment or health advice.

## 20 — GitHub
- [ ] Push the R project, README, citation and output tables.
- [ ] Make meaningful incremental commits.
- [ ] Use pull requests/issues if team collaboration is required.
- [ ] Follow the instructor's exact rules for stars/contributions; never buy or fake engagement.
